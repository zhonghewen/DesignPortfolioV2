Evolving Seller Support into Conversational AI @Amazon

Evolving Amazon's legacy seller support page into a conversational multi-agent assistant — defining inline interaction patterns and the quality bar for each rollout phase.

Role
Tools

The Problem

Amazon Seller Central's traditional help page was migrating to an AI assistant. The challenge was twofold:

  • Functional parity — Maintain all existing functionality in a significantly smaller conversational interface
  • Metrics protection — Ensure the migration didn't harm key business metrics like seller satisfaction and contact rates
02 / 07

Challenge 1 — Feature Parity in Constrained Space

Design Approach

The AI assistant panel is significantly smaller than the traditional help page, making it impossible to display all features the same way.

With no clear requirements from stakeholders on how to prioritize them, I used interaction data and past UX research to make trade-off decisions — prioritizing the most frequently used features on the landing view while keeping less frequently used features conditionally rather than upfront.

Challenge 2 — Designing for a Flow You Can't Predefine

Design Approach

Unlike the old rule-based flow where every seller followed the same fixed path, the new agentic flow is entirely context-dependent. The agent dynamically generates the flow based on:

  • Prior conversation
  • Data retrieved via tools
  • Seller input — meaning no two flows are the same

You can't predefine a single path.

Left — Traditional self-service flow (rule-based)  ·  Right — Support agent flow (context-dependent)

My Approach

Instead of designing end-to-end flows, I identified the smallest interaction unit as the foundational building block — modular components the agent assembles dynamically based on context. Working with SMEs, I mapped key use cases and broke them into atomic units.

Examples of atomic unit types — Selection, Selection with description, ID input field, and Mutating actions.

But defining the units alone wasn't enough. I needed to show how they work together in a real agentic experience — and that's where new challenges emerged:

Sellers can choose to chat with the agent at any point instead of engaging with an inline interaction unit, pushing it out of view. Forcing sellers to scroll back creates friction.

To address this, I designed the agent to regenerate contextually relevant suggestions based on the conversation — so the flow always moves forward, never backward.

When a seller chats instead of selecting an inline unit, the agent regenerates contextually relevant suggestions — keeping the flow moving forward.

These real-world scenarios made clear that we needed a set of principles to guide trade-off decisions consistently across all cases:

  • Minimal input — Use tools to find answers independently before asking sellers. When input is needed, ask up to three questions max — anything more warrants an open canvas
  • Single turn — Avoid complex navigation inline; keep interactions simple and contained
  • Continuity — Sellers can use chat at any point to get help without losing their place in the flow
  • Efficiency — Batch related inputs together. When sellers can click to select, never ask them to type

Resource Constraints & Phase Zero Decision

Scoping Down to a Minimum Viable Version

The Constraint

Implementing the full design required significant development resources. Working with the product team, we scoped phase zero down to a minimal viable version that excluded all sixty-seven self-service workflows and most inline interactive components.

The Result

An almost entirely text-based conversational experience — far from the modular, interactive vision, but a deployable starting point to gather real-world signal.

04 / 07

Validation

I partnered with a UX researcher to validate this scoped-down version through seller interviews, comparing the text-based and interactive experiences.

Key findings:

  • Sellers preferred the interactive units and flagged efficiency — fewer turns, click instead of type — as a clear improvement area
  • However, satisfaction scores remained comparable between both experiences

"It would have been easier if you could see the options or key information needed in one go and easily select the answers instead of having to type them out."

— Amazon Seller

While sellers preferred the interactive experience, the comparable satisfaction scores gave us confidence that the text-based version was an acceptable starting point given our constraints.

Phase 0 Design

Phase 0 — the text-based conversational experience launched to gather real-world signal before building out the full interactive component system.

Impact

The Phase 0 launch showed promising early signal alongside a critical problem that shaped the next phase.

Next Steps

  1. Integrate all sixty-seven self-service workflows
  2. Build the inline interactive units to reduce back-and-forth and drive down abandonment rates
07 / 07

Reflection

Good UX judgment means distinguishing necessary changes from nice-to-haves. Some battles are worth fighting — like pushing back on stakeholders to customize landing topics toward support-relevant content, backed by research. Others are better validated in production than debated upfront.
