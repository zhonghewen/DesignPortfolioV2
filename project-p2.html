Unifying AI Tools for Complex Support Cases @Amazon

Integrating multiple AI tools into the existing case handling interface to reduce average case handling time and drive associate adoption.

The Problem

Five-plus tools, constant context-switching, and a wave of incoming AI widgets — all in one interface.

Amazon support associates handle complex seller cases using five or more features simultaneously. The current interface forces constant back-and-forth navigation, reducing efficiency and increasing cognitive load during high-stakes interactions.

At the same time, multiple AI tools were being developed in parallel — an issue summary widget, an execution widget, a response generator, and an associate assistant. Each team was building independently, creating a risk of a fragmented, bolt-on experience that would make the existing workflow worse, not better.

The Challenge: How do you integrate multiple AI tools into a complex, live interface — without disrupting what already works for the associates who depend on it every day?

02 / 06

Step 1 — Understanding Current Workflows

Shadowing associates to find where AI tools could add value — and where they'd create friction.

Before designing anything, I needed to understand how associates actually worked. I conducted associate shadowing sessions to map their workflow into three core stages:

01.

Understanding the issue — reading case history, seller context, and prior contacts to build a mental model of the problem

02.

Selecting the right solution — navigating across tools to identify the correct resolution path, policy, or escalation route

03.

Replying to the seller — drafting and sending a response that is accurate, empathetic, and meets quality standards

This revealed the key friction points — and, critically, exactly where AI tools could add real value versus where they might interrupt a flow that already worked.

03 / 06

Step 2 — Mapping Widgets to Architecture

Organizing a fragmented set of AI tools into a coherent, structured system.

With the workflow mapped, I categorized both existing features and incoming AI widgets into three functional areas based on where they fit in the associate's process. I then consulted SMEs on two key dimensions:

  • Frequency of use — how often does each tool appear in a typical case, and does that justify primary versus secondary placement?
  • Importance to resolution — how critical is each tool to reaching a correct outcome, and what happens if it's buried or missed?

From this, I identified the information flow between tools — which outputs from one widget fed directly into the next — giving us a clear picture of natural groupings and dependencies.

Key Insight

The AI Tools Were Solving Three Different Jobs

Understanding

Issue summary and case context tools reduced the time associates spent reading — compressing a 20-minute case history into an actionable brief.

Decision-making

The execution widget and associate assistant supported resolution selection — surfacing the right policy, escalation path, or action at the right moment.

Communication

The response generator reduced drafting time by generating a structured seller reply, leaving associates to review and refine rather than write from scratch.

04 / 06

Step 3 — Prototyping & Navigating Pushback

Testing consolidation scenarios with PMs — and aligning on what phase zero would actually deliver.

Based on AI confidence levels and usage frequency, I prototyped consolidation scenarios showing how widgets could be grouped, merged, or eliminated — then validated feasibility with product managers across the involved teams.

This surfaced three significant pushbacks that shaped the final direction:

01.

Layout concerns — PMs raised questions about how widgets would visually coexist without overwhelming the interface or competing for attention

02.

Tier complexity — Different associate tiers use different widget combinations, making a single unified layout difficult to design without excessive conditionality

03.

Scope creep risk — Too many secondary tools were being proposed for a single phase, threatening timeline and launch quality

How I Navigated Them

  • Aligned PMs on a single future-state interface for all associate tiers — eliminating the need to design multiple tier-specific variations and reducing the layout debate to one shared vision
  • Scoped phase zero to six core widgets: issue summary, execution widget, response generator, correspondence, annotation, and reply — the highest-frequency, highest-impact tools across tiers
  • Deferred the associate assistant orchestrator to a later phase based on timeline constraints and technical feasibility, keeping phase zero achievable and coherent
05 / 06

Outcome

A clear unified vision and a pragmatic roadmap — with full impact being measured.

Phase zero established a clear, unified interface vision and a pragmatic roadmap for integrating AI tools into the associate case handling workflow. Rather than a fragmented set of independently developed widgets, the team now had a shared architectural direction and a scoped delivery plan.

Full impact on case handling time and associate adoption is currently being measured as the phase zero build progresses.

Reflections

What integrating AI into a live enterprise workflow taught me.

  • 01. Deep Workflow Understanding Before New Patterns Designing for internal tools requires mapping what already exists before introducing anything new. The shadowing sessions revealed that associates had developed efficient workarounds for the interface's shortcomings — and any AI integration that disrupted those workarounds would face immediate resistance, regardless of how well-designed it was.
  • 02. Pragmatic Phasing Is Critical for AI Integration When integrating AI into complex legacy systems, the temptation is to solve everything at once. Scoping phase zero to the six highest-impact widgets — and explicitly deferring the orchestrator — made the difference between a credible launch plan and an indefinitely delayed one. The roadmap gave PMs confidence without overpromising.
  • 03. Influencing Strategy Requires Evidence, Not Opinion Getting PMs aligned on a single unified interface — rather than tier-specific variations — required showing, not telling. Prototyping the consolidation scenarios made the tradeoffs concrete and moved the conversation from abstract debate to actionable decision-making. Evidence-based prototyping is how designers earn a seat at the strategy table.
